# Signed artifact runner

`scripts/sign-desktop-artifact.mjs` operates on one independently accepted unsigned universal app. It does not build the application, replace identifiers or provisioning material, modify fuses, or treat signature removal as a byte-equivalence test. The unsigned and signed Mach-O hashes remain distinct. The shared custody observer limits each signing step to one declared primary and its exact signature resources.

The implementation and synthetic tests do not authorize or demonstrate actual signing, Keychain access, notarization, AAC, Gatekeeper first use, or either physical Mac's acceptance. An actual invocation requires a separately approved execution window and existing signing/notary handles. The public approval receipt records that authority; creating a JSON file does not create authority that the operator lacks.

## Inputs and ownership

The strict descriptor has exactly `schemaVersion: 1`, `kind: "signed-desktop-artifact-inputs"`, `artifact`, `tooling`, `policy`, `signingSteps`, `authorization`, and `nativeHelper`.

- `artifact` contains the original six-field `identity`, `source: {commit, tree}`, `ci: {commit, verificationRunId, securityRunId, receipt}`, `universalCheckpoint`, `inventory`, and `treeSha256`. Its source and CI agree with the embedded identity. Its source may differ from the signing tooling's source. The universal checkpoint is an independently admitted public snapshot; the runner never opens the original native checkpoint for writing. It checks all directly referenced original sidecars and derives the app path from the fixed `universal-artifact-runs/<runId>/candidate/DesmosLock Internal.app` layout.
- `tooling` contains its separate source and CI records, the exact positive `sourceManifest`, pinned dependency records, and twelve fixed tool pins: `node`, `codesign`, `codesignAllocate`, `ditto`, `hdiutil`, `notarytool`, `stapler`, `spctl`, `stat`, `xattr`, `ls`, and `sandboxExec`. A manifest row has `path`, `mode`, `gitBlob`, `sha256`, and `bytes`; a dependency row has `name`, `version`, `packageJsonSha256`, and `integrity`. Only the runner's finite positive paths are admitted. The Node executable is checked against the running executable. Tool hashes, names, and explicit paths are pinned; no identity, credential, tool, or account-history discovery runs.
- `policy` is a pin to the closed shared `signed-artifact-policy`. `signingSteps` is the ordered array of pins to its exact object rows. The runner rederives the entire inside-out plan from the admitted unsigned inventory and policy on create and every resume, then compares the retained plan. A self-hashed retained plan cannot add signature paths. Standalone Electron crashpad is handled only through the observer's fixed helper form.
- `authorization` contains the uppercase public leaf `signingIdentitySha1`, nonsecret `notaryKeychainProfile` handle, and `executionApproval` pin. The approval record has exactly `schemaVersion`, `kind: "signed-artifact-execution-approval"`, `runId`, `artifactIdentity`, `unsignedCheckpointSha256`, `unsignedAppTreeSha256`, `policySha256`, `toolingProvenanceSha256`, `signingIdentitySha1`, `certificateChainSha256s`, `notaryKeychainProfile`, `teamId`, `trustedHostCustody: "exclusive-reviewed-host"`, and `authorizedOperations`. The latter is the exact sequence `copy`, `sign-app`, `create-sign-dmg`, `submit-one-dmg`, `reconcile-known-id`, `staple-dmg`, `assess`, `readonly-inspection`. All bindings are checked before work. Certificate fingerprints are public information, never private keys.
- `nativeHelper` pins the existing fixed `artifacts/unsigned-artifact-tools/durable-record.node`. A pin is exactly `{path, sha256, bytes}`. Paths are explicit normalized nonsecret paths with no symlink ancestors. Artifact descendants use the separate custody grammar that permits ordinary spaces and parentheses. Input JSON and normal sidecars are bounded to 64 MiB; selected tool binaries are bounded to 256 MiB.

Each CI receipt is a closed public record with `schemaVersion: 1`, `kind: "accepted-artifact-ci"`, `sourceCommit`, `verificationRunId`, `securityRunId`, and `verification`/`security` both `"success"`. The receipt must already have been independently checked against the actual run; local parsing does not query GitHub or establish CI authenticity.

The tooling manifest also requires the two exact runtime execution files `packages/contracts/dist/build-identity.js` and `packages/contracts/dist/exact-record.js`. Their accepted build lineage belongs to tooling review, separate from the app's source. For these emitted files, `gitBlob` is the Git blob content hash of the measured bytes; it does not assert that an ignored output is tracked by the tooling commit. Source and emitted-runtime pins must both match before artifact commands are admitted. The operator still starts from an independently trusted tooling checkout; self-checks cannot establish the authenticity of their own executable code.

The plan binding hashes recursively ASCII-key-sorted compact descriptor JSON with one final newline. Tool provenance is the same encoding of the tooling record. File pins always hash original file bytes, not reserialized JSON. The separately derived custody-plan hash uses the observer's documented encoding. Neither hash is a self-hash.

## Invocation and stages

Only these forms are accepted, using the pinned Node 24.20.0 executable on Darwin:

```text
node scripts/sign-desktop-artifact.mjs create --run-id <UUIDv4> --inputs <absolute-descriptor-path>
node scripts/sign-desktop-artifact.mjs resume --run-id <UUIDv4>
node scripts/sign-desktop-artifact.mjs reconcile --run-id <UUIDv4>
node scripts/sign-desktop-artifact.mjs readback --run-id <UUIDv4>
```

Output stays under `artifacts/signed-artifact-runs/<runId>`. The runner takes the same checkout collector lease used by unsigned collection. It never automatically reclaims a retained lease. The native owner enforces a single process/store writer, monotonic checkpoint revisions, sidecar integrity, 64 attempts, a 60 KiB checkpoint ceiling and recovery headroom.

The twelve fixed stages are input validation, custody copies, one `sign-code` stage per object, signed-app verification, DMG creation, DMG signing, one notary submission, known-ID reconciliation, DMG stapling, DMG verification, inspection-copy mount, and checkpoint readback. There is no caller-defined workflow, command, hook, shell, environment, output directory or fallback signer.

Before a mutation, a reservation binds the complete current custody observation, target full/slice hashes, immutable index/step, tools, policy, and exact signing arguments. The native owner publishes that reservation and commits pending before calling the operation. The callback reobserves the current input after this await boundary. A resolved `recordStage` is inspected for an actual matching `observed-pass`; failure is never interpreted as success.

Copies use fixed `ditto --rsrc --extattr --acl --qtn` into absent destinations. Actual tree and metadata equality is checked. Unknown attributes, ACLs, resource forks, flags, changed quarantine, or unsupported metadata fail closed. File and directory mtimes remain exact; recreated destination symlink times are explicitly recorded. The existing quarantine-copy counterexample is not waived.

Subsequent operations on the same work copy load the prior successful output inventory through its directly checked sidecar reference. The entire new custody observation must equal that retained snapshot before another transformation: unchanged content hashes do not excuse changed inodes or timestamps. Device/inode and permitted symlink-time differences belong only to the explicitly observed copy boundary.

Signing uses fixed `codesign` arguments and the declared requirement; no deep signing is used. The pinned allocator is selected explicitly. The signing child is confined to the selected work/scratch paths and reviewed signing facilities. Product execution is absent from its executable allowlist. Child confinement and an exclusive lease do not exclude every unrelated same-user host process: trusted host custody remains an explicit assumption.

Every code object is verified strictly across all architectures, followed by explicit arm64 and x86_64 observations of identifier, Team, timestamp, CodeDirectory hash, runtime flag, exact entitlements, designated requirement, and extracted public certificate chain. The outer recursive verification supplements this enumeration. Empty entitlement stdout alone is refused: the pinned tool must produce an explicit empty plist or supported explicit absence observation. Unsupported tool-output formats stop the run and need a reviewed adapter correction, not a relaxed parser.

The final signed app is frozen before creating the read-only DMG once. That DMG is signed, submitted without waiting, and its ID and pre-staple hash are committed before any status query. Reconciliation only reads that exact ID. An in-progress observation stops normally without stapling; an accepted response also requires the uploaded hash and ticket coverage of the expected code objects and both architectures. Only the DMG is stapled. Its post-staple hash is a different immutable candidate. No app staple or second image submission occurs.

Final checks include image checksum, signature, stapled ticket and Gatekeeper assessment. A byte-identical owned inspection copy is mounted read-only at a fixed owned mountpoint, compared to the signed app, and detached by the exact returned device identity. A failed or unidentified mount/detach is uncertain. These checks never claim first offline Finder use or physical protection.

## Recovery and verification limits

An interrupted or failed mutation remains recorded and cannot advance or replay. A lost submission ID cannot be recovered by listing account history or submitting again. Known-ID reconciliation may retry only an explicitly marked, finite nonzero exit from its exact `info` or `log` command after the owner confirms child and stream settlement without another owned-work failure. A thrown callback, failed evidence write, invalid returned result, or contradictory replay instead records permanent `observation_failed` with a null per-attempt notary status. The last real Apple status is retained, but even an earlier or later valid acceptance cannot remove this mutation block. No Apple rejection is invented. A valid Rejected or Invalid response records the actual rejected status without attempting optional diagnostic publication. The pending reservation already binds the submitted image and known ID; recording either finite failure does not require a diagnostic sidecar. Changed submitted bytes, invalid info/log/ticket observations, missing coverage or contradictory facts stop the sequence.

An unconfirmed child/stream, native close, or mount settlement retains the checkout lease and evidence. Review is required before any new runtime attempt; no boolean reset or automatic cleanup manufactures certainty. Normal completion closes and reopens the actual native owner, revalidates its retained references, then records readback. Completed resume also remeasures the submitted/final DMGs and the retained signed work-copy snapshot before returning candidates; it never repeats a mutation to recreate missing evidence. App-tree readback observes the correctly selected original or work copy before claiming current input validation. A readback after recorded failure explicitly reports history only, without claiming partially changed artifact bytes were revalidated or unblocking mutation.

Synthetic tests call the explicitly named `ForTesting` entrypoint with synthetic commands and a synthetic storage adapter. They test dispatch, bindings, pending-before-command, failure and retry behavior; they do not establish native durability, command-format fidelity, signing, notarization, confinement effectiveness, metadata-copy fidelity, or physical acceptance. Those remain separately authorized, artifact-bound runtime gates. All physical pending cases remain pending after this runner.
